LSX EXPORT BUG ANALYSIS - CRITICAL FINDINGS
============================================

ROOT CAUSE: Silent error handling combined with unsafe dynamic imports

THREE CRITICAL ISSUES FOUND:

1. UNSAFE DYNAMIC IMPORTS (Line 250-252 in lsxExport.ts)
   Problem: const [{ default: jsPDF }, { default: html2canvas }]
   - Assumes .default export exists
   - If import fails or exports differently, jsPDF becomes undefined
   - new jsPDF() then throws: TypeError: jsPDF is not a constructor
   - Error caught at line 304 but only logged generically
   Probability: 85%

2. UNSAFE STRING OPERATIONS (Line 302 & 570 in lsxExport.ts)
   Problem: order.snapshot.customer.replace(/\s+/g, '_')
   - No null check before calling .replace()
   - If customer is null/undefined, throws TypeError
   - Error caught but only logged generically
   Probability: 70%

3. SILENT ERROR HANDLING (Line 344-346 in LSXFormModal.tsx)
   Problem: catch (err) { console.error(...); alert('generic message'); }
   - Error only logged to console
   - User sees generic "Có lỗi khi xuất file"
   - User never learns what actually failed
   - Makes debugging impossible in production
   Probability: 100% (affects all cases)

IMPACT: When user clicks export button:
- Order IS saved to database (success)
- Export function IS called (attempted)
- Export FAILS silently (jsPDF/html2canvas/data issue)
- Error is caught and hidden
- User sees generic error

- User thinks entire feature is broken
