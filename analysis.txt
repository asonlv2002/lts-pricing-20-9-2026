2. CREATION - addCurrentToHistory()
   File: src/store/calculatorStore.ts (Lines 206-240)
   
   Process:
   - Creates HistoryItem with timestamp id
   - Deep copies state.input
   - Captures result.finalPrice, result.structureText
   - Sets quoteStatus = 'drafted'
   - Prepends to history array, keeps max 200
   - Saves to localStorage immediately
   - POST to /api/history (fire-and-forget)

3. LOADING - loadHistoryItem()
   File: src/store/calculatorStore.ts (Lines 257-269)
   
   Process:
   - Finds item in state.history by id (no server call)
   - Deep copies item.input to form
   - Recalculates result with current config
   - Restores chotGia
   - Switches to calculator view

6. DATABASE PERSISTENCE
   File: src/lib/db.ts
   
   readHistory(): data/history.json or []
   writeHistory(): data/history.json with atomic write + lock
   
   Write locking prevents concurrent corruption
   Atomic write (.tmp then rename) prevents crash corruption

7. LIFECYCLE FLOW
   
   User Input
     ↓
   addCurrentToHistory()
     ├→ localStorage (sync)
     └→ POST /api/history (async)
     ↓
   state.history updated
     ↓
   QuotationModule renders
     ├→ AdminView (grouped by seller)
     └→ SaleView (filtered by seller)
     ↓
   Click card → loadHistoryItem()
     → restore input + recalculate
     ↓
   Edit form
     → Save again → new HistoryItem
     ↓
   Status updates:
     → updateQuoteStatus() → PATCH /api/history/:id
     ↓
   Price updates:
     → setChotGiaForLatest() → PATCH /api/history/:id

9. KEY PATTERNS
   
   Dual persistence: localStorage (sync) + Server (async)
   Immutability: Spread operators only
   Deep copy: Input copied on save/load
   Guarded mutations: id and input protected in PATCH
   Idempotent POST: Checks for duplicate id
   Fire-and-forget: Server calls don't block
   Recalculation: Result recalculated on load with current config
